## Project Summary

UConnect (repo name `get-together`) is a mobile-first social/group-formation platform built as a pnpm monorepo with `apps/web` (Next.js + Tailwind), `apps/api` (Fastify + Prisma + Supabase), `apps/mobile` (Expo/React Native scaffold), and a Postgres schema using pgvector and PostGIS. The product lets UW students set weighted interests, "group seekings" (e.g., "want a study group of 3"), swipe on candidates, and be auto-placed into formed groups with a chat.

## Suggested Improvements & New Features

### Code Quality & Technical
- **Actually use the embeddings.** In `apps/api/src/services/matchingScoring.ts`, add a path that pulls the 768-d vectors from `InterestEmbedding` and computes a semantic similarity term that is summed into `matchScore`. Right now you're paying the cost of running a Docker GPU/CPU model and storing pgvector data with an IVFFlat index but the discovery query never touches it. A 5-line `pgvector <=> ` query in `matchingDiscovery.ts:collectCompatibleSeekingHits` would let users match on "machine learning" ↔ "deep learning" even when interest IDs don't overlap exactly.
- **Deploy.** Pick Vercel (free for the web app) + Supabase Cloud + Fly/Render for the API. Even a password-protected staging URL satisfies the rubric. Without a live URL the project literally cannot be graded against the *Deployed Application* deliverable.
- **Trim "temp" commits**: `53b6c58 temp` and `dc64398 temp commit` are unprofessional in a graded history; squash before final submission. The 5 "Potential fix for pull request finding" commits should also be squashed.
- **Add CI**: `.github/workflows/ci.yml` running `pnpm lint`, `pnpm typecheck`, `pnpm -r test` on PRs. `CONTRIBUTING.md:38` already recommends this but it isn't enforced.
- Either build out `apps/mobile` (it currently has only `app/index.tsx` and `app/_layout.tsx`) or remove the mobile claim from the README.
- Polling chat (`apps/web/src/components/GroupChatClient.tsx`) was supposed to be replaced by sockets per commit 7077784 — confirm the polling fallback is removed and the realtime path is wired through Supabase Realtime end to end.

### UI / UX Improvements

### New Features
- **UW SSO gating.** Require an `@uw.edu` email on signup (Supabase Auth supports domain restriction) so the community-impact claim is real.
- **Course-based interests.** Pull SLNs from the UW Time Schedule public pages and seed them as interests, so "CSS 382 Spring 2026" becomes a one-click study-group seeking. This is concrete, UW-specific, and unique.
- **Location-aware: campus-only mode.** You already store PostGIS locations and `distanceBuckets.ts` returns coarse buckets. Add a geofence that filters discovery to the UW Seattle/Bothell/Tacoma campuses and surfaces UW building names ("HUB", "Mary Gates Hall") in `friendlyName`.
- **Event proposals tie into UW calendars.** Commit c5e1d4b adds "propose events/activities in group chat" — extend this to import UW events from the UW Events Calendar feed so groups can RSVP to real campus things.

### AI Integration Enhancements
- **Semantic interest expansion (highest-leverage win).** When a user types a free-text interest, use the existing TEI/all-mpnet-base-v2 service to embed it and nearest-neighbor query `InterestEmbedding` (cosine, pgvector `<=>`) to suggest the 5 closest canonical interests. This makes the AI *user-facing* and *load-bearing*, not just precomputed.
- **Group-formation re-ranking with embeddings.** In `groupFormation.ts:compatibleCandidates`, blend the current `normalizedWeightedOverlap` score with a semantic score = mean cosine distance between the seed user's interest centroid and the candidate's centroid. Two users with non-overlapping but semantically-close interests would then match.
- **LLM-generated group "icebreaker" prompts in chat.** When `ensureProposalGroupChat` first creates a chat, post a system message generated by an LLM (Claude or a small open model) that proposes a first activity based on the group's shared interest names + city. This makes the AI visible in the user's daily flow.
- **Bio quality assistance.** Use an LLM to nudge users when their bio is empty or single-word in `apps/web/src/app/profile/page.tsx`, suggesting 2–3 prompts based on their top-weighted interests.
- **Embedding-based duplicate-interest cleanup.** The interest catalog (`packages/db/prisma/interest-data.json`) inevitably accumulates near-duplicates; a one-shot script using your existing embeddings would identify clusters with cosine > 0.9 and flag them for merge.
